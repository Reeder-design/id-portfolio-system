Portfolio Manager

User Guide

Use Portfolio Manager as a private working studio around your public portfolio: manage existing work, prepare source material safely, create new work from a reviewed brief, preview local changes, and publish only when you explicitly approve them.

AI Settings Back to Dashboard

If you forgot everything, start here

  1. Start Portfolio Manager: from the repository root run python portfolio-manager/app.py. If you normally use the project virtual environment, activate it first. Open http://127.0.0.1:5055.
  2. Start the real portfolio preview: run cd portfolio, then python3 -m http.server 8000.
  3. Choose your goal: use Manage Content for work that already exists, or Create Content for new portfolio work and private source preparation.
  4. Work locally first: edits, AI proposals, private notes, Reference Library files, Content Briefs, and controlled builds stay local until you deliberately move approved work through publishing.
  5. Preview before publishing: inspect the real local page, run Full Validation, then use Save & Publish only when you are satisfied.

Memory shortcut: manage or prepare → review → preview → validate → publish.

The three kinds of work

  • Manage: edit pages and projects that already exist in the public portfolio. This includes visible copy, project data, project assets, page-aware AI changes, Related References, and portfolio-wide AI review.
  • Prepare: use the private Content Workspace & Reference Library inside Create Content to store originals, add notes, analyze sources, sanitize them, and approve separate public-safe derivatives.
  • Create: start with an idea or approved sanitized source, build a Content Brief, generate a project plan, approve the plan, create a reviewed local build, then move through preview and publishing.

The Dashboard intentionally has only two main cards—Manage Content and Create Content. Prepare is part of Create because Reference Library material exists to support future portfolio work.

Where information lives

  • .env: local secrets such as the Portfolio Manager password hash, Flask secret, and optional OpenAI API key. Git-ignored. Never put this information into portfolio files.
  • .portfolio-manager/: private working data such as notes, AI proposals/reviews, backups, Content Briefs, Reference Library originals and derivatives, upload sessions, and other local workflow records. Git-ignored.
  • portfolio-data/: Git-tracked structured portfolio content and system records. Treat it as publishable repository content; do not store secrets or confidential source material there.
  • portfolio/: public-candidate website files and managed public assets. Anything placed here may become publicly reachable after publishing.

Rule of thumb: confidential source material belongs in Reference Library, not in portfolio/ or portfolio-data/.

Manage Content

Manage Content mirrors the public portfolio hierarchy. Start with Home, About Me, Projects, or Contact, then move through the same categories, landing pages, and demos a visitor sees.

The interface hides implementation details whenever possible. You should not need to know whether a page is powered by structured JSON, custom HTML, CSS, JavaScript, or a renderer just to make a normal content edit.

Page editors

  • Current visible content: safely editable headings, paragraphs, labels, buttons, list items, and other recognizable copy from the real page.
  • Interactive states: supported text shown after clicks, tabs, or other interaction states.
  • Private page notes: reminders, future ideas, feedback, or missing pieces stored only in the private Portfolio Manager workspace.
  • AI-assisted edit: plain-English requests for structural, visual, interaction, or code-heavy changes that are easier to describe than expose as form fields.
  • Live local preview: the real page served from port 8000.
  • Save Edits: saves local changes and runs the relevant safeguards. Saving never publishes by itself.

Project editors and assets

Project editors keep project identity and structured content connected so titles, references, documentation, and standard case-study pages stay consistent. Custom experiences such as MEDDPICC Practice, Pursuit Determination Lab, and AI Evaluation also link directly into their full visible-page editor.

Project Assets now live directly inside the relevant project and custom-page editors. You can upload, preview, edit alt text/captions, replace, and remove managed project assets without leaving the content workflow. The full Asset Library remains available as an advanced view.

Uploading an asset associates it with the project but does not automatically insert it into a public page layout. This prevents a file upload from unexpectedly rewriting a custom experience.

Public-safe confirmation is required for uploads and replacements. Images require alt text. Removal is blocked when Portfolio Manager detects that public HTML/CSS/JavaScript still references the file.

Page-aware AI edits

Use the AI-assisted edit area when a requested change is structural, visual, interaction-heavy, or code-heavy—for example: “make these cards the same height,” “turn this explanation into a reveal interaction,” or “make this spacing match the other sections.”

For a page-aware request, Portfolio Manager sends the selected public page, the public design-system CSS needed for context, and the request you typed. Private notes, Reference Library files, local credentials, Git history, and unrelated repository files are excluded.

The workflow is:

  1. Describe the change.
  2. Review the private AI proposal and exact anchored edits.
  3. Choose Approve & Apply Locally only when the proposal is acceptable.
  4. Portfolio Manager rechecks the source, creates a backup, applies only the approved operations, and runs validation.
  5. Preview the real local result.
  6. Keep the local change or Revert it from the backup.
  7. Publish later through the normal publishing workflow.

AI cannot independently commit, push, publish, or merge a page change.

Related References

When a saved change affects a project/page identity that may be referenced elsewhere—such as a title—Portfolio Manager can open a deterministic Related References review.

This step does not use AI. It searches the managed public content for connected references and lets you decide each one individually: Update Reference, Edit Suggested Text, or Leave Unchanged.

Reference updates are validated and rolled back if the portfolio becomes inconsistent. They still remain local until publishing.

AI Portfolio Review

AI Portfolio Review analyzes the public portfolio only. It is useful for professional QA, clarity, consistency, evidence gaps, portfolio positioning, and improvement opportunities.

The current review is advisory and unified rather than three separate review modes. It does not edit pages, apply proposals, use private Reference Library content, perform Git actions, or publish. Current review does not perform web research.

Reference Library: private source preparation

The Content Workspace & Reference Library is the private preparation area nested under Create Content. Store source material here when it may be useful later but is not ready to become public.

Supported private items can include documents, spreadsheets, presentations, PDFs, images, HTML, ZIP packages, and small video files. The original source is preserved unchanged.

Reference items move through statuses such as Private Source, Needs Review, Sanitization In Progress, Sanitized Draft, and Approved for Portfolio Use. Approval is only allowed after a separate sanitized derivative exists.

Approved for Portfolio Use does not publish a file. It means the sanitized derivative is eligible to be used as trusted source context in Create Content.

Ask AI About This Resource

This Reference Library tool answers questions such as: What skills does this source demonstrate? What evidence is actually present? What evidence is missing? What portfolio pieces could it support? What is reusable? Where might it fit?

  • Text-extractable files: Portfolio Manager extracts text locally and shows the exact text before anything is sent.
  • PNG/JPEG/WEBP images: Portfolio Manager shows the actual image before sending it. Image pixels are not locally OCR/preflighted, so a separate visual-content acknowledgement is required.
  • Not sent: private notes, tags, approval notes, unrelated Reference Library resources, and local credentials.

The AI result stays attached to the private Reference Library item. Analysis does not sanitize, approve, create public files, or publish anything.

Sanitization review

Sanitization is a separate workflow from general AI analysis. AI can flag possible risks; you decide what happens to every finding.

Typical findings include company/customer/product names, unreleased information, metrics, URLs, systems, proprietary terms, personal information, logos/branding, filenames, and other context clues.

For each finding you can choose actions such as Keep, Remove, Generalize, Rewrite, Replace text/asset, Crop or redact, or mark the content intentionally public-safe. The original private source is never overwritten.

The result becomes a separate Sanitized Draft. You must still review that derivative and explicitly approve it before it can be attached to a Content Brief.

Create Content Lab

Create Content starts with the idea and evidence before it starts with page generation.

  1. Content Brief: define what you are making, why, audience, story, evidence, interaction, visual direction, public-safety constraints, and personal direction.
  2. Approved Sources: optionally attach approved sanitized derivatives from Reference Library. The private original is not attached to the brief.
  3. AI Content Plan: after the brief is saved, AI can propose the concept, format, placement, sections, interactions, assets, evidence gaps, safety notes, build tasks, and writing direction.
  4. Approve Plan for Build: the current plan requires explicit human approval before a controlled build can begin.
  5. Build Proposal: AI converts the approved brief/plan and approved source context into the structured fields used by the standard case-study system. No public files are written yet.
  6. Human review: edit the exact proposed public content before creating anything.
  7. Create Local Project & Validate: Portfolio Manager writes the reviewed project locally, refreshes generated docs, and runs validation. It rolls the new project back if validation fails.
  8. Preview → Keep or Revert: inspect the real local project. Keep it when you want to continue, or revert the controlled build.
  9. Continue toward publishing: a kept build moves into Related References and then the normal preview/validation/publishing workflow.

Advanced AI Drafting Helper

The Advanced AI Drafting Helper is a supporting tool for isolated rewriting, analysis, placement suggestions, summarization, or drafting. It is not the main Create Content workflow.

You can paste text or attach supported documents/images. File requests follow a reviewed boundary:

  1. Prepare locally first.
  2. Review the exact extracted text and any images AI would receive.
  3. Confirm provider/authorization and any sensitivity or visual acknowledgements.
  4. Generate a private proposal.

Temporary upload sessions are Git-ignored. Binary uploads are removed after successful generation or when you explicitly discard the prepared request.

After reviewing a proposal, choose Use in Existing Content, Create Something New, or Save for Later. Existing-content handoff stages the draft in the real editor; it does not auto-save. Content Brief handoff prefills fields for review; it does not create the brief until you save it.

AI Settings

Open AI Settings from the Dashboard, User Guide, or an AI-enabled workflow. The OpenAI API key is stored only in the local Git-ignored .env file.

  1. Enter an OpenAI API key.
  2. Choose the Portfolio Manager model: GPT-5.6 Terra for the balanced default, GPT-5.6 Sol for stronger reasoning/code work, or GPT-5.6 Luna for lighter lower-cost tasks.
  3. Select Save AI Settings.
  4. Select Test Connection to verify the configured provider/model can respond.

The full API key is never shown back in Portfolio Manager. API usage/billing is separate from a ChatGPT subscription.

AI and privacy: what gets sent

Portfolio Manager does not send the whole repository to AI. Each AI surface has a narrow context:

  • Page-aware edits: selected public page + relevant public design-system CSS + your request.
  • AI Portfolio Review: public portfolio content only.
  • Advanced AI Drafting Helper: only the pasted/reviewed extracted text, reviewed images, your task, and the allowed public taxonomy/context for that request.
  • Reference resource analysis/sanitization: only the source content you explicitly review/authorize for that action plus limited public taxonomy/context where needed.
  • Create Content planning/building: the saved Content Brief, current plan when applicable, public taxonomy, and attached approved sanitized derivatives. Private originals are not used as approved-source context.

Provider and authorization acknowledgements appear before external AI calls when private or user-supplied material may be sent. Credential-like text can block an AI request before sending.

AI safety boundaries

  • AI may propose, analyze, flag, or draft. Human approval remains required for local writes, source sanitization decisions, approved-source status, and publishing.
  • AI is instructed not to invent employers, clients, products, metrics, credentials, outcomes, or other unsupported professional claims.
  • Page-aware AI edits are anchored to the exact source version you reviewed and are rechecked before application.
  • Generic proposal handoff stages draft text into an editor form only; it does not auto-submit or auto-save.
  • Reference AI analysis cannot change sanitization/approval status.
  • Controlled Create builds can write local portfolio files only after plan approval, proposal review, public-safety acknowledgement, and validation. They do not commit or publish.
  • No AI workflow has authority to force-push, silently merge, or independently publish the portfolio.

Publishing

Local edits are not live. Local validation is not live. A local Git commit is not live. The explicit Publish to GitHub action is what pushes approved committed main changes to GitHub, where GitHub Pages can deploy the public site.

  1. Finish the relevant Manage/Create/Related References work.
  2. Preview the real local page.
  3. Run Full Validation.
  4. Open Save & Publish.
  5. Review changed files and select exactly what belongs in the commit.
  6. Inspect the diff.
  7. Use Validate & Commit Changes. This creates a local checkpoint only.
  8. Use Publish to GitHub only when you approve the committed result.

Portfolio Manager blocks private/sensitive paths, force-push, silent merge/rebase behavior, publishing with uncommitted changes, and publishing when GitHub has newer commits that require reconciliation.

Privacy & security

  • Portfolio Manager binds to 127.0.0.1 and is intended for local use.
  • It requires the local Portfolio Manager password and protects modifying forms with CSRF tokens.
  • Sessions expire after eight hours. A timeout does not delete work.
  • Secrets live in Git-ignored .env; private workflow/source data lives under Git-ignored .portfolio-manager/.
  • Reference Library originals remain private and unchanged. Sanitized derivatives are separate files.
  • Files copied into portfolio/ are public-candidate files even before they are visibly linked from a page.
  • Git publishing controls reject known private paths and sensitive file types.
  • External AI receives only the context disclosed by the specific AI workflow after required review/acknowledgements.

The Privacy & Security help topic provides the short version from anywhere in Portfolio Manager.

Advanced Maintenance

Refresh Documentation rebuilds generated maintenance documentation. View Documentation opens the repository documentation. Version Release records an intentional patch, minor, or major system release.

These tools are deliberately separate from normal Manage/Create workflows and do not publish by themselves.

What is still intentionally deferred

  • Theme Editor: curated theme changes remain deferred rather than exposing raw CSS as the normal editing experience.
  • Visual sanitization automation: text sanitization is guided; image/visual redaction still requires human-controlled handling.
  • Additional AI Review lenses/web research: the current Portfolio Review is one public-portfolio advisory review without web research.
  • Final publishing UI polish: the underlying publishing safeguards are active, while the long-term goal remains a more human-facing Preview → Approve → Publish surface with technical details secondary.

Technical terms you may still see

  • Local: stored on your Mac/working copy, not live on the public portfolio.
  • Validation: automated checks that verify the portfolio, content records, workflow guardrails, and Portfolio Manager runtime remain consistent.
  • Sanitized derivative: a separate reviewed working copy of private source material. The original remains unchanged.
  • Approved Source: a sanitized derivative explicitly approved as eligible source context for Content Briefs. Approval does not publish it.
  • Proposal: AI-suggested content or changes awaiting human review.
  • Staged draft: proposal text inserted into an editor form for review but not yet saved.
  • Commit: a saved Git history checkpoint.
  • Publish / push: send approved committed changes to GitHub.
  • API: the external connection used when you intentionally send a reviewed AI request.

When something goes wrong

  • Session expired: sign in again. Your files remain on disk.
  • Preview is blank: make sure the preview server is running from portfolio/ on http://127.0.0.1:8000.
  • AI says setup is needed: open AI Settings, save an API key, and run Test Connection.
  • AI request is blocked: review the sensitivity/credential warning. Do not bypass a warning unless you are authorized and understand exactly what will be sent.
  • Reference source cannot be approved: create/store a separate sanitized derivative first, then add an approval note and approve that derivative.
  • Content plan is stale: refresh or regenerate the plan after changing the brief or approved source context.
  • Asset removal is blocked: the file is still referenced by public code; update those references before removing it.
  • Validation fails: do not publish. Read the specific failure first; guarded workflows usually roll back the affected local change automatically.
  • Publish is blocked: check for uncommitted changes or newer GitHub changes.
  • Unexpected Git changes: inspect Save & Publish or run git status. Do not reset/delete files simply to clear a warning.

To stop Portfolio Manager or the preview server, press Control + C in that server's terminal.
