Portfolio Manager

User Guide

Use Portfolio Manager like a content studio. Choose what you want to do, edit the portfolio in familiar page order, preview your changes, then publish only when you approve the result.

Back to Dashboard

If you forgot everything, start here

  1. Start Portfolio Manager: from the repo root run source .venv/bin/activate, then python portfolio-manager/app.py. Open http://127.0.0.1:5055.
  2. Start the portfolio preview: from portfolio/ run python3 -m http.server 8000. The editors use that real local site for preview.
  3. Choose Manage Portfolio Content: navigate through Home, About Me, Projects, portfolio areas, and projects in the same order visitors see them.
  4. Edit the page: change the connected visible content and use the live preview for context.
  5. Save Edits: the edit remains local. Saving does not publish the portfolio.
  6. Run Full Validation: use the current publishing tools on the dashboard while the v2 guided publishing wizard is being built.
  7. Save & Publish: review the changed files, commit the approved local changes, then explicitly publish them to GitHub.

Current memory shortcut: manage → edit → preview → validate → publish.

What the three main workspaces mean

  • Manage Portfolio Content: edit work that already exists publicly. This is available now and is the normal editing path.
  • Create Portfolio Content: the upcoming Create Content Lab for brainstorming, planning, briefing AI, and building new portfolio work.
  • Content Workspace & Reference Library: the upcoming private area for source materials, notes, sanitization, analysis, and approved portfolio-ready derivatives.

Create Content and the private Workspace are deliberately shown before their functionality is added so the navigation can grow around the final v2 mental model instead of being redesigned again later.

Manage Portfolio Content

The manager mirrors the public portfolio hierarchy. Start with Home, About Me, Projects, or Contact, then move through the same portfolio areas and projects that appear on the site.

Edit means the page already has a safe editing connection. Preview only means the page is represented in the correct hierarchy but its exact editable regions have not been connected yet.

Preview-only pages are not missing from Portfolio Manager. They are intentionally visible so you always know where they belong and which editor connection still needs to be built.

Page editors

Editors should show recognizable content from the actual public page rather than implementation metadata.

  • Current visible content: text areas already connected safely to the public page.
  • Live local preview: an embedded view of the real page being served from port 8000.
  • Open Full Preview: opens the same local page in a separate browser tab.
  • Save Edits: updates the local portfolio only. It does not publish by itself.

Private page/project notes will be added in the next editor slice and will not be stored in public portfolio content.

Project pages

Projects can use a shared portfolio layout or contain a custom-coded interaction. Portfolio Manager handles that distinction underneath the interface.

For a shared-layout project, the editor can expose the visible introduction, challenge, audience, role, goals, design approach, development, results, tools, and skills because those values directly build the visible case-study page.

For a custom interaction, Portfolio Manager currently exposes only content that has a known safe connection. For example, a project title can be synchronized without rewriting the interaction. Other custom visual or behavior changes will move through the later plain-English AI editing workflow.

The goal is that you do not need to know whether a page is technically generated or custom in order to manage it safely.

Assets

During the v2 transition, project editors link to the existing safe Asset Library. It manages files deliberately approved for the public portfolio.

Asset controls will move directly into each page/project editor later so text, images, captions, alt text, and AI help can live in one workspace.

Do not upload confidential, proprietary, customer-identifying, or unsanitized material into the public asset library.

What is coming next

  • Private page/project notes: notes attached to one page or project that never publish automatically.
  • Related References: after an edit, Portfolio Manager will find other connected references and offer inline actions such as Update Reference, Edit Suggested Text, or Leave Unchanged.
  • Guided publishing: Related References → Preview → Approve → Publish will replace the need to think about Git steps during normal editing.
  • AI-assisted page edits: plain-English requests for copy, spacing, colors, and custom interaction/code changes with proposal, preview, validation, and approval before application.
  • AI Portfolio Review: separate Professional QA, SME/Compliance, and Improvement reviews of the public portfolio only.
  • Private Content Workspace: source storage, AI analysis, sanitization review, approved derivatives, and handoff into the Create Content Lab.

Privacy and future AI behavior

  • Public Portfolio Review will inspect only the public portfolio unless you explicitly provide additional context.
  • Private reference-library materials will remain separate from public portfolio review.
  • When you intentionally ask AI to analyze private material, the interface should explain what will be sent to the configured provider.
  • Sanitization will be a human-reviewed pipeline, not a one-click guarantee that a source is safe.
  • Original private sources will remain unchanged; sanitized derivatives must be explicitly approved before they become eligible for portfolio use.

Publishing during the v2 transition

The existing validation and Git publishing engine remains in place while the guided publishing UI is built.

  1. Save your page/project edits.
  2. Preview the local result.
  3. Run Full Validation.
  4. Open Save & Publish.
  5. Review the changed files and diff.
  6. Use Validate & Commit Changes to create a local checkpoint on main.
  7. Use Publish to GitHub only when you approve the update.

A local commit is not public. Publishing pushes committed main changes to GitHub, where GitHub Pages can deploy them.

Advanced Maintenance

Refresh Documentation rebuilds the generated content inventory, portfolio map, and changelog. Normal page editing should not require you to think about these files.

View Documentation opens the documentation folder on GitHub.

Version Release records an intentional patch, minor, or major portfolio-system release. Use it for meaningful system releases rather than routine copy edits.

Technical terms you may still see

  • Local: stored only on your Mac. Not live on the public portfolio.
  • Validation: automated safety checks that make sure the portfolio structure, links, content records, documentation, and publishing rules still agree.
  • Commit: a saved local history checkpoint. It is not public until pushed.
  • Publish / push: send approved committed changes to GitHub so GitHub Pages can deploy them.
  • GitHub Pages: the service that hosts the public portfolio from the GitHub repository.
  • API: the connection Portfolio Manager will use to send an intentional AI request to the configured AI provider.

Technical details that are useful only for troubleshooting should continue moving out of the normal editing interface and into Advanced/System Info.

When something goes wrong

  • Session expired: sign in again. Your files are still on disk.
  • Preview is blank: make sure the local preview server is running at http://127.0.0.1:8000.
  • Port 5055 is already in use: an older Portfolio Manager process is probably still running.
  • Validation fails: do not publish. Read the failure message and fix the specific issue first.
  • Publish is blocked: check whether there are uncommitted changes or newer GitHub changes that need to be synchronized.
  • Unexpected Git changes: inspect Save & Publish or run git status. Do not reset/delete files just to clear a warning.

To stop Portfolio Manager or the preview server, press Control + C in that server's terminal.
