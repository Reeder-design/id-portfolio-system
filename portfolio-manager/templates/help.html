Portfolio Manager

User Guide

A zero-context guide to editing, saving, and publishing your portfolio without needing to remember the underlying Git mechanics.

Back to Dashboard

If you forgot everything, start here

  1. Start Portfolio Manager: from the repo root run source .venv/bin/activate, then python portfolio-manager/app.py. Open http://127.0.0.1:5055.
  2. Edit what you need: use Project Content, General Page Content, Asset Library, or optional AI Assistance.
  3. Preview the result: public-site edits remain local on your Mac until you publish.
  4. Run Full Validation: this is a read-only health check.
  5. Open Save & Publish: review changed files, select what belongs in the next commit, and inspect the diff.
  6. Validate & Commit Changes: Portfolio Manager validates again and saves a local Git checkpoint on main.
  7. Publish to GitHub: only when you are satisfied. This pushes committed main changes to GitHub, where GitHub Pages can deploy them.

Memory shortcut: edit → preview → validate → commit → publish.

Session timed out? Sessions expire after eight hours. Your files are not deleted. Sign in again if Flask is still running, or restart it with python portfolio-manager/app.py.

Dashboard quick reference

  • Project Content: create or edit structured project records. Standard pages can be regenerated; custom interactive pages are protected.
  • General Page Content: edit approved plain-text fields on managed public pages with validation and rollback.
  • Asset Library: manage files deliberately approved for the public portfolio.
  • AI Assistance: create private proposals. AI cannot apply changes, commit, or publish.
  • Run Full Validation: read-only portfolio health and safety check.
  • Save & Publish: review → select files → validate + commit locally → explicitly publish to GitHub.
  • Advanced Maintenance: Refresh Docs and Version Release are low-frequency tools, not required for routine edits.

The mental model

Portfolio Manager operates on your local clone of id-portfolio-system.

  • Local edit: a file changed on your Mac. Not live.
  • Local commit: a validated Git checkpoint saved on local main. Still not live.
  • Publish to GitHub: pushes committed main changes to origin/main. This can trigger GitHub Pages deployment.
  • Private runtime: .env and .portfolio-manager/ are ignored by Git and are not part of the public site.
  • Public website: files under portfolio/ are what GitHub Pages can publish.

Key rule: commit and publish are intentionally separate so you can save a clean checkpoint before anything goes live.

Starting and signing in

From the repo root:

source .venv/bin/activate

python portfolio-manager/app.py

Open http://127.0.0.1:5055. The app binds only to localhost and normal debug mode is disabled.

Initial secure setup uses python portfolio-manager/setup.py. You do not rerun setup just because a session expired.

Privacy and security

  • .env contains the local Flask secret, password hash, and optional AI API key and is ignored by Git.
  • .portfolio-manager/ stores private runtime data such as AI proposal history and is ignored by Git.
  • Authenticated sessions expire after eight hours.
  • Every modifying POST action requires a CSRF token.
  • The app runs only on 127.0.0.1.
  • Save & Publish blocks private runtime paths and common key/certificate files from staging.

General Page Content

This is the safe editor for routine copy on Home, About, Projects, Instructional Design, AI Training and Evaluation, Workflows, and Contact.

The source of truth is portfolio-data/site-content.json. Only approved headings and paragraphs are exposed; raw HTML is not.

Saving updates the structured value and its approved public HTML location locally, then validates. If validation fails, both changes are rolled back.

Saving does not commit or publish. Preview the page, then use Save & Publish when ready.

Project Content

New Standard Project creates structured project data and a standard case-study page when appropriate.

Save Project Data edits portfolio-data/projects/*.json. Validation failure rolls the JSON edit back.

Standard page: edit JSON → save → regenerate page → preview → Save & Publish.

Custom page: metadata can be edited, but the generic renderer cannot overwrite bespoke HTML/CSS/JavaScript.

Public Asset Library

The Asset Library manages files you have intentionally approved for the public portfolio.

Managed files live under portfolio/assets/project-assets/<project-id>/. Anything under portfolio/ may become publicly reachable after publishing.

  • Add Public Asset: copies an allowed file and records metadata. Images require alt text.
  • Save Metadata: updates alt text or caption.
  • Replace File: replaces bytes at the same path; validation restores the old file on failure.
  • Remove Asset: removes the association and public file, with reference checks and rollback protection.

Keep confidential, proprietary, customer-identifying, or unsanitized source material outside the public portfolio.

AI Assistance

AI Assistance is proposal-only. It supports Rewrite & Polish, Sanitize for Portfolio, Analyze Source Content, Suggest Placement & Tags, and Draft Project Summary.

Only source/context you deliberately enter is sent, plus the public portfolio taxonomy. Local project pages and arbitrary files are not automatically sent.

AI cannot edit public files, edit structured JSON, commit, or publish. Approved wording must be copied into the appropriate deterministic editor.

If you are not authorized to send source material to an external AI service, do not paste it into AI Assistance.

Configuring AI

AI is optional. Portfolio Manager works normally without an API key.

Enable later with python portfolio-manager/configure-ai.py. Disable with python portfolio-manager/configure-ai.py --disable.

The key/model stay only in the Git-ignored local .env. Restart Portfolio Manager after changing AI configuration.

Run Full Validation

This is a read-only health check covering site links/assets, structured content, renderers, project generation, documentation, Git guardrails, AI guardrails, and Portfolio Manager security/runtime rules.

It changes nothing. Use it after meaningful edits. Save & Publish runs the same suite again immediately before commit.

Save & Publish: Step 1, review files

The page shows every local Git change and whether it is already selected for the next commit.

Select Files for Commit stages only the exact safe files you choose. Private runtime paths such as .env, .portfolio-manager/, and .venv/ are blocked.

Remove Selected removes a file from the next commit without deleting the local edit.

Use the diff review to confirm exactly what changed before committing.

Save & Publish: Step 2, commit

Validate & Commit Changes runs the full validation suite first. If anything fails, Git does not create the commit.

A successful commit is saved directly to your local main. This is your checkpoint/history entry.

A local commit is not public. Nothing reaches GitHub until you use Publish to GitHub.

Save & Publish: Step 3, publish

Publish to GitHub pushes committed local main changes to origin/main.

Before pushing, Portfolio Manager refreshes GitHub status. Publication is blocked if GitHub has newer commits or if uncommitted local changes remain.

Force-push, silent merge, and silent rebase are not implemented.

After a successful push, GitHub Pages can deploy the updated public portfolio.

Sync Main with GitHub

When the working tree is clean, Sync Main with GitHub uses git pull --ff-only origin main.

Fast-forward-only means the manager refuses a sync that would require a merge commit. It never discards local edits.

You do not need to create a feature branch before ordinary Portfolio Manager edits.

Advanced Maintenance

Refresh Docs rebuilds generated maintenance documentation such as inventory, map, and changelog. It does not refresh the public website or publish anything.

Version Release records an intentional patch, minor, or major portfolio-system release. Use it for meaningful system releases, not routine copy edits.

When something goes wrong

  • Session expired: sign in again. Your work is still on disk.
  • Port 5055 is already in use: an older Portfolio Manager process is probably still running. Stop that process before restarting after branch/code changes.
  • Portfolio preview port 8000 is already in use: use the existing preview server or stop it before starting another.
  • Validation fails: do not commit. Fix the issue and rerun validation.
  • Publish is disabled: check for uncommitted changes, no local commits waiting to publish, or GitHub being ahead of your local main.
  • You are on another Git branch: routine Portfolio Manager save/publish actions are intentionally available only on main. Return to main after finishing that development branch.
  • Unexpected Git changes: inspect the Save & Publish diff or run git status. Do not delete/reset files just to remove a warning.

To stop Portfolio Manager or a preview server, press Control + C in that server's terminal.
