The mental model

Portfolio Manager works on your local clone of id-portfolio-system. The safest way to remember the system is:

  • Private workspace: .portfolio-manager/ contains requests, private uploads, backups, and AI proposals. Git ignores it.
  • Structured source: portfolio-data/ contains project records, approved general-page copy, taxonomy, and version data.
  • Public website: portfolio/ contains what GitHub Pages can publish after merge.
  • Git/GitHub: branch → stage → validate + commit → push → PR → explicit review/merge → deployment.

Core rule: AI can propose. Structured editors can write approved local content. Git Workflow can prepare a PR. Only an explicit merge can make approved public files deploy.

Starting Portfolio Manager

From the repository root:

source .venv/bin/activate

python portfolio-manager/app.py

Then open http://127.0.0.1:5055. The app is bound to localhost, normal debug mode is off, and your login settings live in the Git-ignored .env.

Privacy and security

  • .env stores the local Flask secret, password hash, and optional AI API key. It is ignored by Git.
  • .portfolio-manager/ stores private runtime material and is ignored by Git.
  • All dashboard pages except login/static assets require authentication.
  • Every modifying POST form requires CSRF protection.
  • Sessions expire after eight hours.

Private does not mean “safe to share externally.” You are still responsible for deciding whether source material is appropriate to send to an AI provider or publish publicly.

AI Assistance

AI Assistance is proposal-only. It can help with Rewrite & Polish, Sanitize for Portfolio, Analyze Source Content, Suggest Placement & Tags, and Draft Project Summary.

The only source/context content sent to the configured AI provider is what you deliberately enter in the AI workspace, plus the repo's public portfolio taxonomy so placement suggestions use your real categories. It does not read project pages, private requests, uploaded source files, or arbitrary repository files.

Before sending, the local preflight blocks several obvious credential formats such as private keys, OpenAI-style API keys, GitHub tokens, AWS access keys, and bearer tokens. This is a safety net, not a substitute for your review.

You must confirm that you understand the provider boundary and that you are authorized to send the text.

Configuring AI

AI is optional. Portfolio Manager works without it.

To enable it, run:

python portfolio-manager/configure-ai.py

The helper adds OPENAI_API_KEY and PORTFOLIO_MANAGER_AI_MODEL only to your local .env and preserves the existing Portfolio Manager login settings. Restart Flask afterward.

The default model is gpt-5.6-terra, but the model is configurable. OpenAI API usage is billed separately from a ChatGPT subscription.

To disable AI locally without changing your Portfolio Manager password:

python portfolio-manager/configure-ai.py --disable

Reviewing an AI proposal

AI proposals are saved under .portfolio-manager/ai-proposals/ and remain outside Git.

The review page separates:

  • proposed copy
  • analysis/rationale
  • suggested category, subcategory, and tags
  • source-supported claims
  • missing or unsupported claims
  • confidentiality/publication warnings

The source text is retained in that private local proposal so you can audit what the AI actually saw.

There is intentionally no AI Apply button. Approval means copying the wording you accept into General Page Content or Project Content and saving through that deterministic editor.

Sanitize mode: what it does and does not do

Sanitize mode can generalize identifying employer, customer, product, roadmap, launch, or internal-process details and flag remaining publication risks.

It does not make confidential input safe to send. If you are not authorized to send source material to an external AI service, do not paste it into the AI workspace. Use already-generalized notes instead.

It also cannot guarantee that a result is legally or contractually safe to publish. Human review remains required.

Requests and private uploads

Request a Change and New Content Request save private work orders. They do not perform the requested edit automatically.

Use them for future ideas or private/reference source material you want to keep local. These files are not automatically fed into AI Assistance.

General Page Content

This is the safe editor for predefined plain-text fields on Home, About, Projects, Instructional Design, AI Training and Evaluation, Workflows, and Contact.

It updates portfolio-data/site-content.json and only the matching approved text location in public HTML. It does not expose raw HTML, CSS, JavaScript, navigation, or layout.

Every save requires a public-safe confirmation, escapes managed copy as plain text, validates immediately, and rolls back both source + HTML if validation fails.

Project Content

Structured project data lives under portfolio-data/projects/. Save Project Data updates the JSON record and refreshes generated documentation.

Standard page: generated from structured data + shared template and can be regenerated after edits.

Custom page: bespoke HTML/CSS/JavaScript interaction. Portfolio Manager may update metadata JSON but does not let the generic renderer overwrite the custom experience.

Public Asset Library

The Asset Library is for files you have intentionally approved for the public portfolio. Managed files live under portfolio/assets/project-assets/.

Because those files are under portfolio/, they may become publicly reachable after merge even when no page visibly links to them.

Images require alt text. Replacement preserves the existing extension/path. Removal checks references and rolls back if a public dependency still exists. Web-code/executable formats remain blocked from the uploader.

Run Full Validation

This is a read-only health check. It checks the public site, structured project/general-page content, renderers/generator, documentation/versioning, Git workflow safety, AI-assistance safety, and Portfolio Manager security/runtime behavior.

Git Workflow runs the full suite automatically before creating a commit.

Refresh Docs and version releases

Refresh Docs rebuilds maintenance documentation about the portfolio. It does not refresh public HTML.

Patch: small fixes. Minor: meaningful new project/feature. Major: major redesign/architecture shift.

A version bump changes local version/history documentation; it does not commit or publish by itself.

Git Workflow

  1. Sync Main Safely: fast-forward-only pull on clean main.
  2. Create & Switch Branch: create a local feature/, fix/, content/, or chore/ branch.
  3. Review + Stage: choose exact changed files for the next commit.
  4. Diff Review: inspect the actual line-level staged/unstaged changes.
  5. Run Validation & Commit: validation must pass before the commit can be created.
  6. Push Feature Branch: normal upstream push only.
  7. Open Pull Request: GitHub CLI when available, otherwise GitHub's pre-filled PR page.

Commits/pushes on main, force-push, arbitrary shell execution, private-path staging, and merge are intentionally unavailable.

What actually becomes public?

GitHub Pages deploys from portfolio/ after approved changes reach main.

The normal chain is:

local change → stage → validation + commit → push feature branch → PR → explicit merge approval → GitHub Pages.

Private requests, private uploads, API credentials, and AI proposal history never belong in that chain.

When something goes wrong

Keep the Flask terminal open while using Portfolio Manager. If a browser action errors, the terminal usually contains the useful Python message.

Run git status before deleting/resetting anything. Uncommitted local changes are usually recoverable.

Stopping Flask with Control + C does not delete files or undo work.
