Portfolio Manager

User Guide

Use Portfolio Manager like a content studio. Choose the portfolio page you want to work on, edit what you can see, use AI only when it helps, preview the result, and publish only when you approve it.

AI Settings Back to Dashboard

If you forgot everything, start here

  1. Start Portfolio Manager: from the repo root run source .venv/bin/activate, then python portfolio-manager/app.py. Open http://127.0.0.1:5055.
  2. Start the portfolio preview: from portfolio/ run python3 -m http.server 8000.
  3. Choose Manage Portfolio Content: navigate through the portfolio in the same hierarchy visitors see.
  4. Edit what you see: change visible page text directly. Interactive states appear in their own section when connected.
  5. Use private notes: save page-specific reminders or ideas without publishing them.
  6. Use AI for larger changes: describe structural, visual, interaction, or code-heavy changes in plain English. AI creates a private proposal first.
  7. Preview and validate: inspect the local result and run Full Validation before publishing.
  8. Save & Publish: review the changed files, commit approved local changes, then explicitly publish them to GitHub.

Memory shortcut: manage → edit or propose → preview → validate → publish.

What the three main workspaces mean

  • Manage Portfolio Content: edit work that already exists publicly. This is the normal editing path.
  • Create Portfolio Content: the planned Create Content Lab for brainstorming, planning, briefing AI, and building new portfolio work.
  • Content Workspace & Reference Library: the planned private area for source materials, notes, sanitization, analysis, and approved portfolio-ready derivatives.

Manage Portfolio Content

The manager mirrors the public portfolio hierarchy. Start with Home, About Me, Projects, or Contact, then move through the same portfolio areas, landing pages, and demos that appear on the site.

Normal editing should not require you to know whether the page is driven by structured data, custom HTML, CSS, JavaScript, or another implementation detail. Portfolio Manager keeps that distinction underneath the interface.

Page editors

  • Current visible content: headings, paragraphs, labels, buttons, list items, and other recognizable copy from the public page.
  • Interactive states: text shown after clicks, tabs, or other supported interaction states.
  • Private page notes: reminders, ideas, objectives, or future changes stored only in the private Portfolio Manager workspace.
  • AI-assisted edit: plain-English requests for changes that are easier to describe than expose as form fields.
  • Live local preview: the real page being served from port 8000.
  • Save Edits: updates local content only. Saving does not publish by itself.

Project pages

Project identity, especially the project title, is kept connected to the project record so references and documentation can stay consistent. The project editor then leads into the visible-page-copy workspace for the rest of the custom page.

This means MEDDPICC, Pursuit Determination, and AI Evaluation use one normal project entry point while still letting you edit the visible custom-page content.

AI Settings

Open AI Settings from a page editor or the User Guide. Portfolio Manager stores the OpenAI API key only in the local Git-ignored .env file.

  1. Create an OpenAI API key in the OpenAI API dashboard.
  2. Paste it into the API key field.
  3. Choose the default model. GPT-5.6 Terra is the balanced default, GPT-5.6 Sol is available for stronger reasoning/code work, and GPT-5.6 Luna is the lower-cost option.
  4. Select Save AI Settings.
  5. Select Test Connection to verify the key and model can make a small API request.

The full key is never shown back in Portfolio Manager. API usage and billing are separate from a ChatGPT subscription.

Page-aware AI edits

Use the AI-assisted edit area when the change is structural, visual, interaction-heavy, or code-heavy.

Examples include: “turn the intro into an interactive block,” “make these cards the same height,” “change this box to the mint color,” or “make the spacing around this button match the other cards.”

For a page-aware request, Portfolio Manager sends only:

  • the selected public portfolio page,
  • the public design-system CSS needed for context, and
  • the request you typed.

Private page notes, private reference-library files, local credentials, Git history, and unrelated repository files are not included.

What an AI proposal does right now

The current AI page workflow is intentionally proposal only.

  1. You describe the desired change.
  2. AI reviews the selected public page and public design-system context.
  3. Portfolio Manager requires AI to return exact, uniquely anchored find/replace operations.
  4. You review the plain-English rationale plus the exact current and proposed code.
  5. No public page, Git commit, or GitHub content changes during proposal generation.

The next safety step will add an explicit Apply Proposal Locally action that validates the changed site and returns you to preview before anything can be published.

AI safety boundaries

  • AI cannot publish, commit, push, or merge from the page proposal workflow.
  • The page-edit proposal is stored privately under Portfolio Manager runtime data.
  • Page identity such as the browser title remains outside the AI page-edit boundary.
  • AI is instructed not to invent professional claims, metrics, clients, products, credentials, accomplishments, or outcomes.
  • Proposed code changes must anchor to exact page code that existed when the proposal was created.
  • If a requested change actually requires another file, asset, backend change, or missing information, AI should flag the limitation rather than pretend it completed the work.

Private notes

Private notes are attached to the individual page or project. They are useful for objectives, future changes, feedback, missing assets, or ideas you do not want on the public portfolio.

They are stored in the private .portfolio-manager workspace and are never published automatically or included in page-aware AI requests.

Assets

Project editors currently link to the safe Asset Library. It manages files deliberately approved for the public portfolio.

Asset controls will eventually move further into each page/project workspace so text, images, captions, alt text, and AI help can live together.

Do not upload confidential, proprietary, customer-identifying, or unsanitized material into the public asset library. Private source material will belong in the future Content Workspace instead.

What is still coming

  • Apply AI Proposal Locally: apply an approved proposal, validate it automatically, then return to preview.
  • Related References: find other connected references after an edit and offer inline Update / Edit / Leave Unchanged actions.
  • Guided publishing: Related References → Preview → Approve → Publish.
  • AI Portfolio Review: Professional QA, SME/Compliance, and Improvement reviews of the public portfolio only.
  • Private Content Workspace: source storage, AI analysis, sanitization review, approved derivatives, and handoff into Create Content Lab.
  • Create Content Lab: guided brainstorming, evidence selection, detailed AI briefing, development, review, and publishing for new portfolio work.

Publishing during the v2 transition

  1. Save approved page/project edits.
  2. Preview the local result.
  3. Run Full Validation.
  4. Open Save & Publish.
  5. Review changed files and the diff.
  6. Use Validate & Commit Changes to create a local checkpoint.
  7. Use Publish to GitHub only when you approve the update.

A local commit is not public. Publishing pushes approved committed main changes to GitHub, where GitHub Pages can deploy them.

Advanced Maintenance

Refresh Documentation rebuilds generated maintenance documentation. View Documentation opens the documentation on GitHub. Version Release records an intentional patch, minor, or major system release.

These tools are intentionally separate from normal content editing.

Technical terms you may still see

  • Local: stored only on your Mac, not live on the public portfolio.
  • Validation: automated checks that verify the portfolio still works and its records remain consistent.
  • Commit: a saved local history checkpoint.
  • Publish / push: send approved committed changes to GitHub.
  • API: the connection Portfolio Manager uses to send an intentional AI request to the configured provider.
  • Proposal: an AI-suggested change that has not been applied to the public portfolio.

When something goes wrong

  • Session expired: sign in again. Your files remain on disk.
  • Preview is blank: make sure the local preview server is running at http://127.0.0.1:8000.
  • AI says setup is needed: open AI Settings, save an API key, and run Test Connection.
  • AI connection test fails: verify the API key, selected model, internet connection, and API account billing/access.
  • Validation fails: do not publish. Read the specific failure first.
  • Publish is blocked: check for uncommitted changes or newer GitHub changes.
  • Unexpected Git changes: inspect Save & Publish or run git status. Do not reset/delete files simply to clear a warning.

To stop Portfolio Manager or the preview server, press Control + C in that server's terminal.
