Human Evaluation + Training

How I evaluate an AI response.

I evaluate the response against the task, the evidence, and the rubric. I document what failed, why it matters, and what a better response needs to do. Calibration turns those individual judgments into a consistent review standard.

STEP 01 / TASK + CRITERIA

Read the request before judging the answer.

I establish the task, audience, source boundaries, and rating criteria first. That keeps a fluent response from receiving credit for work it did not do.

USER REQUEST

Write a two-step onboarding message. Include training, manager approval, and where to get help. Use only the source.

01Instruction following02Factual support03Clarity
Review artifact: task requirements + the applicable rubric.
STEP 02 / CLAIMS + OMISSIONS

Mark the exact spans that need investigation.

I read the whole response, then annotate claims and omissions. I separate a factual problem from a writing preference before deciding how serious it is.

A
“Activate automatically”

Does the source promise automatic access?

B
“Within 24 hours”

Is that timeframe supported anywhere?

C
Missing information

No manager approval, help contact, or second step.

Review artifact: annotated response + missing requirements.
STEP 03 / SOURCE COMPARISON

Trace the claims back to the supplied evidence.

I compare each consequential claim with the source. A plausible statement still needs support; an omitted condition can change what the reader does.

SUPPLIED SOURCE

Complete security training. Ask your manager to approve access. Contact Service Desk if approval is delayed.

Training required✓ Supported
Automatic access✕ Contradicted
24-hour promise? No evidence
Review artifact: claim → source → support judgment.
STEP 04 / CRITERION RATINGS

Rate each criterion against an observable anchor.

I assign ratings to the evidence, not to the overall impression. Here, clear wording does not offset missing requirements or an unsupported guarantee.

Instruction followingNeeds correctionTwo-step format, approval, and help contact are missing.
Factual supportNeeds correctionAutomatic activation and a timeframe are unsupported.
ClarityMeets criterionThe sentence is understandable.
Major correctionAnchor: changes an essential condition or omits required action.
STEP 05 / REASON + CORRECTION

Write a rationale that makes the correction actionable.

I connect the issue, evidence, and consequence, then show the required change. The feedback gives a reviewer or author something specific to improve.

IssueThe answer guarantees access without approval.EvidenceThe source requires manager approval and gives no timeframe.ImpactA new starter could wait instead of requesting access.
CORRECTED RESPONSE
  1. Complete security training.
  2. Ask your manager to approve access. Contact Service Desk if approval is delayed.
STEP 06 / SHARED STANDARD

Resolve disagreement, then preserve the learning.

I compare ratings and rationales against the same benchmark. When reviewers disagree, I locate the criterion behind the difference and turn that clarification into reviewer guidance.

REVIEWER AMinor wording issueFocused on readability
REVIEWER BMajor correctionFocused on lost approval
↘   Shared anchor   ↙
Major correction

The response changes a required action. Both reviews use the factual-support anchor.

Training takeaway: Preserve approval conditions; do not infer guarantees. Keep the example, rationale, and anchor together.
