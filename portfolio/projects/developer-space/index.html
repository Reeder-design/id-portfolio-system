MY PRODUCTCode Block Composer

Inside the authoring experience.

I built Code Block Composer because I wanted to create interactive learning without rebuilding the same content, layout, and behavior from scratch. I designed separate paths for visual composition, guided authoring, editable media, and reusable templates so the starting point fits the work.

Build by Blocks

I made the visual editor an independent workspace because authors need direct control over the experience. I kept content, layers, interactions, and motion close to the canvas so each change can be judged in context.

  • Start from a blank canvas, a complete example, or supported HTML/ZIP content.
  • Edit text, images, buttons, tabs, and layers directly.
  • Arrange content and inspect its interaction and responsive presentation.
  • Keep the block together through saving, review, and export.

Why I separated it: Visual authors can build without passing through a guided template.

Fill & Build

I created a guided route because adapting a proven learning pattern should not require reconstructing its interface. I expose the content decisions through mapped fields while the template carries the structure and interaction.

  • Choose a defined learning pattern with a complete worked example.
  • Fill mapped prompts, choices, feedback, and other supported fields.
  • Inspect the generated learner experience as the content changes.
  • Open the generated result in Build by Blocks for visual refinement.

Why I separated it: Guided authoring gives a focused starting point; visual editing provides deeper control.

LayerLift

I built LayerLift because useful source artwork often arrives flattened into an image. I keep the original beside the extracted parts so the author can review recognized text and separable graphic regions before using them.

  • Bring in supported source images for part extraction.
  • Compare recognized text and separable regions with the original.
  • Review and refine the editable result.
  • Save the media for reuse or continue with it inside a block.

Why I kept the source: The original gives the author a reference for checking the result.

Original imageReview partsReuse

Blueprint Builder

I created Blueprint Builder because a finished interaction can become a reusable authoring pattern. I map its editable content and behavior into guided controls while keeping the original learner result available for comparison.

  • Start from a worked example or supported HTML/code-block ZIP.
  • Identify editable words, images, choices, and feedback.
  • Map the fields and behavior that guided authors can change.
  • Prepare a structured template for Fill & Build.

Why it has its own route: Designing a reusable template is a different task from filling one in.
