03 / HOW I BUILD

Curiosity, meet commit history.

I treat each idea like a learning experience: understand the person, sketch the path, build the useful part, test it, then make it easier to maintain.

01

Find the friction

Where is the learner, editor, or builder getting stuck? That becomes the brief.

02

Make it make sense

Map the content, interactions, and interface before adding more buttons.

03

Build the thing

Turn the design into working pages, tools, structured data, and reusable parts.

04

Test, tweak, repeat

Preview, review, validate, ship, and leave a cleaner path for the next version.

My favorite plot twist: the “supporting tool” often becomes a project of its own. Portfolio Manager and Library Manager both started because the upkeep deserved a better experience.

04 / WHAT IT SHOWS

My skill set is a weirdly useful mix.

These projects stretched my instructional design, visual design, and coding skills together. That combination is how I turn a good learning idea into something people can actually use.

01 / THINK

Instructional design

Learning flows, practice, feedback, content structure, and the question behind every screen: “What does someone need to do next?”

02 / SHAPE

Experience design

Clear navigation, helpful interfaces, visual rhythm, and a little personality that makes complex work feel approachable.

03 / MAKE

Code + systems

Working prototypes, local tools, reusable patterns, data structures, and checks that help the good ideas survive the next edit.
